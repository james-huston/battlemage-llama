# Investigations

Living investigation logs for issues that take more than one change to understand
— performance cliffs, model-behavior quirks, flaky interactions between the stack
and its clients. Unlike [`docs/improvements/`](../improvements/) (planned features
with acceptance criteria), these are **open-ended**: we record symptoms,
hypotheses, experiments + results, and what we concluded, updating as we learn.

Each file is one investigation. Keep the **Experiment log** table current — it's
the point. When an investigation reaches a stable conclusion, fold the durable
lessons into the relevant docs (troubleshooting, model `notes:`, memory) and mark
it **Resolved**.
